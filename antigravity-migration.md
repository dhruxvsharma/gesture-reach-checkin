# SmartCare — Touchless Patient Check-In: Codebase Overview & Lovable Migration Guide

## Codebase Overview

**SmartCare** is a touchless, gesture-based hospital kiosk check-in system. Patients interact via hand gestures (tracked by a webcam with MediaPipe) instead of touching a screen — ideal for clinical hygiene.

### Tech Stack

| Layer | Technology |
|---|---|
| Framework | [Vite](https://vite.dev/) v7 + [TanStack Start](https://tanstack.com/start) (SSR-capable router) |
| UI Library | React 19 |
| Styling | Tailwind CSS v4 (`@tailwindcss/vite` plugin) + [shadcn/ui](https://ui.shadcn.com/) (New York style) |
| Animations | Framer Motion |
| State | Zustand-style store in `src/lib/kiosk-store.ts` |
| Hand Tracking | `@mediapipe/tasks-vision` (vision task runner for hand landmark detection) |
| Deployment | Cloudflare Workers via `@cloudflare/vite-plugin` + `wrangler.jsonc` |
| Typography | Google Fonts — Fraunces (headings) + Inter (body) |

### Design System

The app uses a **soft clinical light theme** — no dark mode, no glassmorphism. Key tokens defined in `src/styles.css`:

- **Background:** `#F5F6F4` warm off-white
- **Primary:** `#0F766E` deep medical teal
- **Typography:** Fraunces (headings), Inter (body)
- **Shadows:** Subtle card shadows, no glows

## Lovable.dev Dependency Audit

> [!NOTE]
> The Lovable footprint is **minimal and surgical**. All application source code (components, routes, hooks, styles) is completely Lovable-free. Only the build tooling wrapper needs replacing.

### What Lovable Owns

| Item | File(s) | What It Does |
|---|---|---|
| `@lovable.dev/vite-tanstack-config` | `package.json` (devDep), `vite.config.ts` | Wraps 6 Vite plugins into a single `defineConfig()` call. Also bundles `lovable-tagger` (dev-only component tagging). |
| `.lovable/` directory | `.lovable/plan.md` | AI-generated design plan. Not used at runtime. |
| Bun artifacts | `bunfig.toml`, `bun.lockb` | Lovable uses Bun internally. Not needed for npm/pnpm. |

### What `@lovable.dev/vite-tanstack-config` Actually Does

From the package-lock.json, this package has:
- **1 bundled dep:** `lovable-tagger` (adds `data-lov-id` attributes during dev)
- **6 peer deps it orchestrates:**
  1. `@vitejs/plugin-react` — React JSX transform
  2. `@tailwindcss/vite` — Tailwind CSS v4 Vite integration
  3. `vite-tsconfig-paths` — Resolves `@/*` path aliases from tsconfig
  4. `@tanstack/react-start` — TanStack Start SSR plugin (via `tanstackStart()`)
  5. `@cloudflare/vite-plugin` — Cloudflare Workers build target (build-only)
  6. `lovable-tagger` — Dev-only component tagger (Lovable-specific, not needed)

It also configures: `VITE_*` env injection, `@` path alias, React/TanStack deduplication, error logger, sandbox detection (port/host/strictPort).

## Step-by-Step Migration Instructions

### Prerequisites

- **Node.js** ≥ 18.17 (required by project dependencies)
- **npm** (comes with Node.js) — or pnpm if preferred
- A webcam (for hand tracking features)

---

### Step 1: Replace `vite.config.ts`

The current config imports everything from Lovable's wrapper. Replace it with direct plugin imports.

**Replace the entire contents of `vite.config.ts` with:**

```ts
import { tanstackStart } from "@tanstack/react-start/plugin/vite";
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";
import tsConfigPaths from "vite-tsconfig-paths";
import path from "path";

export default defineConfig({
  server: {
    port: 3000,
  },
  resolve: {
    alias: {
      "@": path.resolve(__dirname, "./src"),
    },
    dedupe: ["react", "react-dom", "@tanstack/react-router"],
  },
  plugins: [
    tsConfigPaths(),
    tailwindcss(),
    tanstackStart(),
    react(),
  ],
});
```

> [!IMPORTANT]
> The `cloudflare()` Vite plugin has been removed from this config because it conflicts with TanStack Start's SSR environment setup during development. Cloudflare Workers deployment can be re-added later using TanStack Start's deployment adapters or a separate build config. The `wrangler.jsonc` file has been kept for reference.

---

### Step 2: Remove `@lovable.dev/vite-tanstack-config` from `package.json`

Remove the Lovable devDependency:

```bash
npm uninstall @lovable.dev/vite-tanstack-config
```

This removes the package and its bundled `lovable-tagger` dependency.

---

### Step 3: Delete Lovable-Specific Files

Remove these files/directories that are Lovable artifacts with no runtime purpose:

```bash
# Remove the .lovable directory
rmdir /s /q .lovable

# Remove Bun-specific files (Lovable uses Bun; we use npm)
del bunfig.toml
del bun.lockb
```

---

### Step 4: Clean Install Dependencies

Delete the old lockfile and `node_modules`, then do a fresh install:

```bash
# Remove stale artifacts
rmdir /s /q node_modules
del package-lock.json

# Fresh install
npm install
```

---

### Step 5: Verify the Dev Server Starts

```bash
npm run dev
```

The app should start on `http://localhost:3000` (TanStack Start default) or the port shown in your terminal.

You should see the **SmartCare** kiosk welcome screen. If you have a webcam connected, the hand tracking system should initialize.

---

### Step 6: (Optional) Verify Production Build

```bash
npm run build
npm run preview
```

This builds the SSR bundle targeting Cloudflare Workers and serves a preview.

---

### Step 7: (Optional) Clean Up `.gitignore`

Your `.gitignore` already ignores the right directories (`.output`, `.vinxi`, `.tanstack/**`, `.wrangler/`). No changes needed unless you want to remove any Bun-related entries.

## Troubleshooting

### `tanstackStart` import not found
The correct import path for TanStack Start v1.167+ is:
```ts
import { tanstackStart } from "@tanstack/react-start/plugin/vite";
```
Older versions may use different paths (`@tanstack/react-start/plugin` or `@tanstack/router-plugin/vite`).

### `@/*` path aliases not resolving (500 error on page load)
TanStack Start creates multiple Vite environments (client + SSR). The `@/*` alias must resolve in **all** environments. Use both `vite-tsconfig-paths` plugin AND explicit `resolve.alias` in your config — `resolve.alias` is the only method guaranteed to propagate to all environments.

### Port conflicts
TanStack Start defaults to port 3000. If it's in use, pass `--port <number>` or configure `server.port` in `vite.config.ts`.

### `@/*` path alias not resolving
Ensure `vite-tsconfig-paths` is in your plugins array, and your `tsconfig.json` has the `"@/*": ["./src/*"]` path mapping (it already does).
